2. HOW THE APP WORKS
==============================================================
Parts:
- Website and logged-in app: Next.js 16, React 19, Tailwind v4. Built into apps/web/.next-build and run by pm2 as nexusforge-web-workspace on port 3300.
- API: Express 5 with Prisma 7 on PostgreSQL 17. Runs as nexusforge-backend-workspace on port 4001. Realtime (chat, presence, voice signalling) runs on socket.io in the same process.
- Database: the app's own PostgreSQL cluster at D:\NexusForgeDB, port 5433 (database nexusforge). Started by scripts\vexora-autostart.cmd at logon. It is not a Windows service, so it does not restart on its own after a crash.
- Gateway: vexora-gateway on port 3400. Sends /api, /socket.io and /uploads to the API, and everything else to the web app.
- Public address: a Cloudflare tunnel (vexora-tunnel) carries nfgcord.com to the gateway.
- Desktop app: an Electron wrapper of the web app. Its updater downloads the installer, checks its SHA-256 against the manifest, and only then installs. The installer is not code-signed yet.
- Owner Console: a local tool (127.0.0.1 only) with a token. It reads the database through a read-only role, reads pm2 and health probes, keeps its own triage store, and can run restarts only when the owner clicks. Dry-run mode blocks all of those actions.
- Watchdog: vexora-watchdog (pm2). A second watchdog script is defined but not running (see section 7).
- Other bots on the same PC: alpha-bot, shadows-ruin, maddobot, trh-bot, smokebot, dynamite-bot, mariadb, ascend-ai. They run under the same pm2.

Request path: browser -> Cloudflare tunnel -> gateway (3400) -> web app (3300) for pages, or API (4001) for /api, /socket.io and /uploads.

Data: 103 accounts, 16 forges, 43 channel messages, 39 direct messages, 7 support tickets (none open), 16 message reports (8 open), 0 active bans, 2 email records in the last 24 hours. Database size 17 MB.
